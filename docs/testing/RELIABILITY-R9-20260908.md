# r9 源码改进与验证记录（2026-09-08）

本轮承接 r8，未覆盖桌面测试包、未发布 GitHub、未操作真实游戏、存档、用户密钥或正式数据库。逐字流式输出未改。桌面仍是 r7a，不包含本轮源码修复。

## 已修复

### 原件备份按游戏安装实例隔离

- 两个安装目录即使游戏相同、文件相同，也分别保存原件，不再共用按游戏名称存放的一份备份。
- 新备份先暂存、校验内容，再原子发布；复制失败不留下可被当成成功备份的半截文件。
- 备份失败向安装事务传播，由已有事务回滚先前替换的文件。
- 目标必须属于当前游戏根目录，备份路径必须属于受控备份目录。
- 兼容旧的实例级备份和当前游戏目录内的旁置备份。
- 无法确认归属的旧游戏级备份返回 backup_ownership_unknown，保留原件、备份和管理记录，不猜测恢复或静默迁移。

代码：modagent/installer.py。tests/test_c0_backup.py、tests/test_install_custom.py 的物理路径断言改为通过备份查询接口验证，仍检查备份内容。

### 只读搜索追问保持原需求

- v2 on 模式下，明确“继续搜索 / search again”和已有搜索的简短限定可以继承同一游戏会话内的原始目标。
- 搜索请求、结果证据筛选和候选收敛使用同一 search_goal，不再搜索时带着原要求、生成清单时却只看最后一句。
- “？”、普通“继续”、取消后的追问不会自动恢复搜索或取得写权限。
- 新明确目标不混入旧目标；切换游戏不继承原会话搜索目标；助手文字不能独自成为授权来源。
- 纯 UI 类查询可通过来源正文中的 overlay 功能证据匹配；名称、具体功能和排除项仍继续核验。
- legacy/off 和 shadow 不启用这条新执行上下文，避免影子观察改变原行为。

代码：modagent/orchestration/router.py、modagent/agent.py、modagent/recommendation_ui.py。

### 卸载界面不再把部分完成当成功

- 单项、批量卸载复用同一结果判断，检查明确状态、保留记录、待处理文件、外部配置清理及错误信息。
- 缺失或矛盾的回执不算成功；仍兼容有明确移除数量或退订成功的旧回执。
- 预览失败不再降级为无预览也能确认卸载。
- 部分完成后刷新清单、保留失败项，并显示尚未全部确认完成的提示。
- 批量统计只计真正成功项，失败项保持选中，避免用户误以为已经全部删除。

代码：electron/src/components/ModsPage.jsx、uninstallOutcome.mjs。

## 未测、限制及后续

- 本轮没有真实模型、真实外部搜索质量或真实游戏安装测试，不能由这些通过率推导模型准确率。
- 隐藏 Electron 测试操作了真实 React 按钮，但服务端返回被模拟；不等同于安装包完整端到端验收。
- 搜索承接仍是有限规则，不能保证任意复合口语都正确理解；“单人可用”等文字保留不代表已证明兼容性。
- 游戏移动到新目录后的旧备份归属需要可靠迁移证据；本轮不自动猜测绑定。
- 跨进程写入隔离、持久执行步骤、崩溃后未知结果对账仍需继续完善；没有宣称恢复链路全部完成。
- 旧卸载工具/更新入口的结果处理需继续逐项审查，不能由本轮 ModsPage 卸载修复推导全部入口一致。
- 用户当前桌面 r7a 没有变更。后续整合独立候选包时再提供包路径、版本和哈希；本轮无新安装包，故无新包哈希。

后续优先继续检查跨进程取消/恢复及其他管理入口的结果一致性，再整合独立测试包，交付“推荐—搜索—选择—下载—安装—管理—卸载”的用户验收任务单。
