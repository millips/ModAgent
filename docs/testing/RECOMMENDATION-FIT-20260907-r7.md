## 本次改动

- 最终候选对照原始需求，而不只看模型改写的关键词。UI+更多信息必须有信息功能证据；纯贴图不能冒充信息增强。
- 已支持功能的中文与否定偏好参与判断。未确认匹配的明确标注，不自动勾选，不编造匹配结论。
- 分开展示详情取得率、需求匹配和功能证据；时间/热度改为来源参考信息，不代替匹配依据。
- 已识别的信息覆盖层作为替代方案比较，优先预选证据覆盖更多或相同的一项，不默认叠加多个同类工具。功能重叠不被谎称为已证实冲突，仍可手动选择。
- 定向信息覆盖层已有两个不同且详情已核验的匹配项后复用结果，不继续盲目扩展。明确要求数量/全部时不使用此停止条件；其他任务保留原预算。
- 同轮不同查询中的同一 Nexus 条目复用详情；不跨用户、跨轮复用这份临时缓存。
- 显示来源返回数、等待的来源、Nexus 详情数、模型/中文说明阶段；合并重复进度，重连沿用同一记录，心跳不再断言网络慢。工具结果新增 source_elapsed_seconds / elapsed_seconds 计时。
- 保留 r6 凭据修复；逐字流式没有改动。

## 验证与边界

新增 13 个 Python 场景覆盖实际原文、正向/否定需求、替代选择、缓存、慢来源进度与取消传播；10 项前端进度断言。r7 全量 113 个回归文件通过；之后 r7a 补充“五个/five mods”的数量要求保护，再跑这 13 个相关场景通过。真实 Chromium/React 模拟传输测试通过，覆盖问答、推荐证据、进度合并、勾选、变体、确认、结果与恢复原选择。

最终 Free/P 打包程序分别通过正常假凭据导入、加密重启、跳过首次配置，以及跨加密上下文的共享凭据不可读/本地保存回退测试。两份包内的后台均与最终后台构建哈希一致。没有把这些测试写成真实模型或真实游戏安装验收。

匹配器不是通用语义理解已经完成的证明：目前明确支持信息、界面、金钱、性能、外观等有限功能条件，未覆盖表达可能标为待确认。仍需多游戏、真实模型评测扩展。

本轮未调用你的真实模型 API，未向真实游戏下载安装或卸载；历史回放、模拟交互不替代真实链路验收。来源网络仍可能慢，本次不承诺固定秒数或网络加速。

来源功能声明不等于兼容性。覆盖层可能需单独运行，并不一定写入游戏目录；必须看计划与安装包核验，不能凭匹配标签跳过确认。

R01—R10 通过后，在备份/专用游戏实例中，用一个低风险可独立卸载的 Mod 继续：搜索 → 选择 → 计划 → 确认 → 下载 → 安装 → 游戏核实 → 管理 → 预览并确认卸载。失败先问原因，明确继续才恢复；检查成功项和目标不丢失、不重复执行。

出现未授权写入、误删、跨游戏候选、取消后新增写入，立即停止并反馈。整套 Agent Core v2 的全部发布门槛尚未在本轮完成验收。
