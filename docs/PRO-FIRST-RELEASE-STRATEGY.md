# ModAgent Pro 首发订阅策略

## 结论

v1.3.0 采用“托管订阅 + 独立设备授权 + 短期签名权益”的首发方案：

- Lemon Squeezy 负责订阅支付、税务、退款、客户门户和许可证生命周期。
- 每个订阅用户获得独立许可证，默认最多激活 2 台设备，允许用户自助停用旧设备。
- ModAgent Pro 不直接把平台管理 API Key、签名私钥或通用解锁密钥放入客户端。
- 一个最小权限的服务端中继接收并验证支付 webhook，再为有效订阅签发 Ed25519 短期权益令牌。
- 在线权益令牌有效期 72 小时；最近成功验证后提供 7 天离线宽限。
- Electron 使用 `safeStorage`（Windows DPAPI）保存许可证和短期令牌；客户端只内置验签公钥。
- 订阅结束或授权撤销后只关闭 Pro 增强能力，用户数据继续可读、可导出、可卸载，不执行自毁或删数据。

## 为什么采用这条路线

它避免首发阶段自行处理银行卡、税务、退款、密码账户和完整许可证后台，同时保留设备撤销、订阅到期联动和后续迁移空间。任何本地桌面软件都无法保证绝对不可破解；本方案的目标是阻止简单复制和共享，并使持续绕过需要反复跟随服务端协议与版本更新。

## 发布边界

### 可以立即公开

- ModAgent v1.3.0 普通版安装包及便携包；
- SHA-256 校验文件、发行说明和开源许可文件。

### 授权接入前只可私有发放

- ModAgent Pro v1.3.0 安装包和便携目录；
- Pro 专有主题、音效和其他订阅资产。

当前 `subscription` 构建标记只区分发行身份，并不证明当前用户拥有有效订阅。因此在服务端权益校验接入并完成绕过测试前，不应将 Pro 安装包作为公开 GitHub Release 附件，也不应开始自动续费销售。需要先行测试时，应使用具名测试用户、独立下载记录和明确到期日。

## 最小上线清单

1. 创建 Lemon Squeezy 月付/年付商品并启用许可证；
2. 部署 webhook 中继，校验签名且按事件 ID 幂等处理；
3. 实现激活、刷新、停用设备和订阅状态查询；
4. 使用 Ed25519 签发 72 小时权益令牌，私钥只存在服务端；
5. Electron、Python 后端和下载/更新入口分别校验权益；
6. 测试退款、取消、拒付、断网、系统时间回拨、设备超限和令牌篡改；
7. 为 Windows 安装包与更新清单配置代码签名；
8. 完成隐私、订阅、退款、客服邮箱和运营主体信息。

## v1.3.0 建议售卖规则

- 套餐：只上 Pro 月付和年付两个选项，减少首发客服复杂度；
- 设备：2 台，用户可自助解绑；
- 离线：7 天；
- 取消：当前计费周期结束后停用 Pro；
- 退款/拒付：服务端撤销权益，保留本地数据与卸载能力；
- 更新：普通版公开通道，Pro 使用仅对有效权益签发的短期下载地址。
