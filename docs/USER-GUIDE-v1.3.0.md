# ModAgent v1.3.0 使用教程

## 1. 安装

普通版使用 `ModAgent-Setup-1.3.0.exe`，P 版使用 `ModAgent-P-Setup-1.3.0.exe`。两者都支持覆盖安装；卸载默认保留 `.modagent` 数据。

安装包当前未签名。如果 Windows SmartScreen 提示未知发布者，请先确认文件名和发布页 SHA256 一致，再决定是否运行。

## 2. 首次配置

首次启动只需要一个大模型 API Key：

1. 选择 DeepSeek、OpenAI / GPT 或自定义 OpenAI-compatible 服务。
2. 填写 LLM API Key。
3. 选择推荐模型或填写服务商给出的模型 ID。
4. Nexus Mods API Key 和 Tavily API Key 可以留空。
5. 保存后进入主界面。

Nexus Key 用于增强 Nexus 详情与下载；Tavily 用于增强跨站搜索。没有它们时，Agent 仍可使用可访问来源、浏览器流程和直接链接工作，但覆盖范围可能下降。

## 3. 导入游戏

优先使用“重新扫描游戏”。未检测到时点击“手动导入游戏”，选择游戏根目录。例如星露谷物语应选择包含游戏主程序的目录，不要直接选择 `Mods` 子目录。

同一游戏存在多个安装位置时，ModAgent 会按实例区分，避免把一个实例的 Mod 状态导入另一个实例。

## 4. 推荐与核验

在对话页说明游戏和目标。推荐表会展示：

- 中文名称/简介与原始名称；
- 来源、版本、更新时间和活跃度；
- 详情核验状态；
- 前置依赖、依赖原因和安装顺序；
- 兼容风险；
- 当前是否可直接安装。

前置依赖排在目标 Mod 前面。勾选按钮不可用时，查看该行原因：可以重新核验、打开来源页、保留目标待后续处理，或下载后使用手动导入。

## 5. 安装与更新

执行前核对最终勾选项和必要依赖。下载先进入临时目录；成功安装后清理本次临时文件，失败时保留足够诊断信息并尝试撤销已修改内容。

更新前确认本地 Mod 的真实来源和 ID。名称相似、来源歧义或详情受阻时，ModAgent 应暂停并要求确认，不能用猜测结果覆盖本地文件。

## 6. 快照

首次管理游戏前创建原版基线快照。安装、更新或批量删除前再创建操作快照。快照用于记录受管文件状态和回滚信息，不替代存档备份；设置或诊断中应以实际占用为准清理旧快照。

## 7. 日志与诊断

设置页提供：

- 检查更新；
- 打开运行日志；
- 复制日志路径；
- 打开配置目录；
- 打开缓存目录；
- 导出诊断。

提交诊断前检查并遮盖私人路径、账号名、Cookie 和 API Key。

## 8. 卸载

标准卸载默认保留 `.modagent`，方便覆盖安装或重装。需要彻底清除时使用 `ModAgent-Cleanup-1.3.0.exe`，并明确勾选“清除稳定版数据”。该操作不可恢复。
