# ModAgent 主题开发与生图适配 SOP

## 1. 目标与适用范围

本 SOP 用于开发 ModAgent 订阅版视觉主题，覆盖：

- 前端现有页面、框体、按钮、展台和浮层的完整换肤；
- 主题专属背景、核心装置、材质等栅格资产的 AI 生图；
- hover、active、disabled、success、warning、error 等交互特效适配；
- 主题切换、氛围光照、自定义壁纸和低动态模式的兼容；
- 开发构建、视觉验收、发行打包和资产授权记录。

核心原则：

1. 文字、图标和动态数据不得烘焙进主题图片。
2. AI 生图负责氛围、装置与材质母版；边框、遮罩、布局和状态反馈保持代码可控。
3. 每个主题必须覆盖所有页面和状态，不能只完成首页截图。
4. 同一主题的背景、框体、按钮和核心展台必须来自同一套材质与光照语言。
5. 先完成风格样张并通过评审，再生成正式资产。

### 2.5 展台与特效载体

当前主要展台是左侧订阅版反馈核心：

- 外部能量场；
- 双层轨道；
- 核心外壳图片；
- 中央镜片；
- 事件结果形状；
- 能量膜；
- DATA 模块；
- 数据通道；
- 粒子层；
- 连击计数；
- 状态标题与事件代码。

现有反馈事件包括：

- UI hover / press / toggle；
- 下载开始、单项完成、批次完成；
- 安装开始、安装完成；
- 删除/卸载完成；
- 扫描；
- 创建快照、回滚快照；
- success、notice、warning、error、cancel；
- enable、disable；
- 连续成功的 combo / peak。

每个新主题必须给这些事件定义统一的运动语言，而不只是换颜色。

## 3. 现有主题维度

当前视觉主题：

1. `core`：科技核心；
2. `modern-tech`：现代科技；
3. `cyber`：赛博霓虹；
4. `galgame`：日式暖金；
5. `soft`：柔光粉雾；
6. `minimal`：极简黑金；
7. `pixel`：像素 CRT。

当前氛围光照：

1. `auto`：智能平衡；
2. `cozy`：温馨暖光；
3. `energetic`：活力霓虹；
4. `romantic`：微醺浪漫；
5. `focus`：深夜独处。

主题和氛围光照必须正交：主题决定材质和基础色，光照模式只叠加环境光，不改变组件语义色。

## 4. 每个主题的标准资产包

### 4.1 AI 生图资产

每个主题先生成以下基础视觉图，并生成覆盖实际控件的 UI 外壳与图标资产。主题不得只交付背景和核心展台。

| `wallpaper` | 3840×2160 | JPG/WebP | 默认背景，中心和左侧保留低信息区 |
| `core-shell-source` | 2048×2048 | PNG | 核心外壳透明化前的高清母版 |
| `core-sphere-source` | 2048×2048 | PNG | 中央能量体/材质母版 |
| `surface-material-source` | 2048×2048 | PNG | 卡片、按钮、边框的材质参考母版 |
| `nav-chat` | 1024×1024 | PNG | 对话导航专属图标 |
| `nav-mods` | 1024×1024 | PNG | Mod 管理导航专属图标 |
| `nav-snaps` | 1024×1024 | PNG | 快照导航专属图标 |
| `nav-settings` | 1024×1024 | PNG | 设置导航专属图标 |

## 5. 各主题生图规划

### 5.1 科技核心 `core`

视觉关键词：深空蓝黑、钛合金、青蓝能量、精密同心结构、控制台。

必须生成：

- 深色舰桥/控制室抽象壁纸；
- 钛合金环形核心外壳；
- 青蓝等离子能量球；
- 深色拉丝金属与微型电路材质。

特效语言：

- 扫描线、环形充能、粒子汇聚；
- 成功向外扩散，错误产生红色断裂环；
- 页面切换使用短距离能量扫描。

### 5.2 现代科技 `modern-tech`

视觉关键词：石墨、银白、磨砂玻璃、克制青光、精密工业设计。

必须生成：

- 极简现代实验室/桌面设备壁纸；
- 银白悬浮机械核心；
- 柔和冰蓝玻璃能量体；
- 阳极氧化铝、磨砂玻璃和细密网纹材质。

特效语言：

- 低幅呼吸、细线描边、短暂高光扫过；
- hover 不超过轻微提亮；
- success 使用白蓝扩散，不使用爆炸粒子。

### 5.3 赛博霓虹 `cyber`

视觉关键词：紫、青、玫红、高反差、雨夜霓虹、全息故障。

必须生成：

- 雨夜未来城区/霓虹机房抽象壁纸；
- 分层全息机械核心；
- 紫青双色电浆球；
- 黑色复合材料、湿润反光与全息纹理母版。

特效语言：

- glitch、色差、霓虹拖尾、快速脉冲；
- warning/error 可加入短促画面错位；
- 必须控制频率，避免持续闪烁影响可读性。

### 5.4 日式暖金 `galgame`

视觉关键词：暖金、紫藤、夕阳、柔焦玻璃、精致日式 UI。

必须生成：

- 黄昏室内/校园窗边的抽象氛围壁纸，不出现人物；
- 金色花瓣结构的悬浮核心；
- 暖金与淡紫玻璃光球；
- 香槟金、磨砂玻璃、细腻纸纹材质。

特效语言：

- 花瓣状光片、柔和散景、缓慢漂浮；
- success 使用暖金光晕；
- error 仍保持清晰红色，不做粉色弱化。

### 5.5 柔光粉雾 `soft`

视觉关键词：粉紫、奶白、半透明软胶、云雾、圆润表面。

必须生成：

- 柔和云雾与渐变光斑壁纸；
- 圆润半透明核心外壳；
- 粉紫乳白能量球；
- 软胶、磨砂亚克力、细颗粒雾面材质。

特效语言：

- 弹性缩放、柔和波纹、低速漂浮颗粒；
- 按钮按下有轻微软体压缩感；
- 禁止过度低对比，正文必须达到可读性要求。

### 5.6 极简黑金 `minimal`

视觉关键词：黑曜石、哑光黑、克制金线、建筑感、无冗余装饰。

必须生成：

- 黑色建筑空间与单束金光壁纸；
- 几何黑曜石核心；
- 小体积金色内核；
- 哑光黑、黑曜石、拉丝黄铜材质。

特效语言：

- 细金线描边、极短高光、几乎无粒子；
- hover 以边缘亮度和 1px 位移表达；
- 所有圆角可降为直角。

### 5.7 像素 CRT `pixel`

视觉关键词：低分辨率像素、CRT 绿、信号蓝、扫描线、复古终端。

必须生成：

- 像素化控制室/终端壁纸；
- 像素机械核心；
- 点阵能量球；
- 像素金属、抖色噪点、CRT 荧光材质。

特效语言：

- 步进动画、像素抖动、扫描线和信号丢失；
- 禁用模糊插值，正式像素资产使用 nearest-neighbor；
- 动画节奏离散化，但不能影响文字阅读。

## 6. 生图执行流程

### 阶段 0：冻结需求

每个主题先确认：

- 主题 ID 和中文名称；
- 3–5 个核心关键词；
- 主色、辅色、危险色；
- 材质；
- 核心装置造型；
- 禁止元素；
- 是否需要独立背景；
- 是否需要替换反馈核心。

未确认主题卡，不进入生图。

### 阶段 1：概念样张

1. 每个主题生成 1 张 `concept-board`。
2. 样张同时表现背景氛围、核心装置、框体材质和按钮材质。
3. 样张不直接进入产品。
4. 评审只选择视觉方向，不讨论像素级实现。

通过条件：

- 与其他主题有明显区分；
- 能覆盖危险、成功、禁用状态；
- 不依赖图片内文字；
- 在深色正文界面上可读；
- 核心装置可被裁为独立透明资产。

### 阶段 2：正式生图

按主题逐一生成：

1. `wallpaper`；
2. `core-shell-source`；
3. `core-sphere-source`；
4. `surface-material-source`。

一次只生成一个不同用途的资产，不能用同一个提示词批量冒充多种资产。

所有生成提示词必须记录：

- 用途；
- 场景/背景；
- 主体；
- 风格和材质；
- 构图；
- 灯光；
- 调色板；
- 必须保留；
- 禁止项；
- 版本号。

统一禁止项：

```text
no text, no letters, no logo, no watermark, no UI labels,
no copyrighted characters, no brand marks, no human figure
```

### 阶段 3：透明化与规范化

核心资产：

1. 使用纯色 chroma-key 背景生图；
2. 去背并检查透明角；
3. 清理色边；
4. 将主体放入 1254×1254 画布；
5. 主体最大直径保持在画布的 82%–88%；
6. 不保留接触阴影；
7. 导出 PNG；
8. 在深色、浅色、红色底上检查边缘。

### 阶段 4：组件资产制作

1. 从材质母版抽取边框语言；
2. 制作按钮、导航和图标框底图；
3. 单独制作发光 Alpha 遮罩；
4. 标记九宫格不可拉伸角区；
5. 以 80px、120px、240px、480px 宽度测试拉伸；
6. 确认文字和图标位于安全区。

### 阶段 5：CSS 与特效适配

每个主题建立：

- CSS 变量：背景、表面、边框、正文、弱化文字、三种强调色；
- 圆角、阴影、字体、材质纹理；
- 按钮六态；
- 卡片、输入框、导航、弹窗、Toast；
- 页面氛围色；
- 核心 idle / hover / press / event / combo 动画；
- `prefers-reduced-motion` 降级；
- 自定义壁纸下的透明度和模糊度。

动画性能约束：

- 优先 `transform`、`opacity`；
- 避免持续大面积 `filter`；
- 粒子由有限 DOM 节点或伪元素完成；
- idle 动画不得持续高频闪烁；
- reduced-motion 下动画时间降至近零，信息仍能通过颜色和形状表达。

### 阶段 6：页面验收

每个主题必须逐项截图：

1. 首次配置；
2. 对话空状态；
3. 对话有消息和工具结果；
4. 对话输入与游戏下拉；
5. 模组列表；
6. 模组下载弹窗；
7. 卸载危险弹窗；
8. 快照列表；
9. 回滚预览弹窗；
10. 设置页；
11. Toast 四态；
12. 下载队列；
13. 调试面板；
14. 核心 success / warning / error / combo；
15. 自定义壁纸模式；
16. reduced-motion 模式。

验收分辨率至少覆盖：

- 1280×720；
- 1600×900；
- 1920×1080；
- Windows 125% 缩放。

### 阶段 7：构建与发行

1. 执行商业资产校验；
2. Vite production build；
3. 检查正式包只引用正式资产，不引用 `concept/` 和 `sources/`；
4. Electron 完整打包，不能只打包无 `node_modules` 的精简 ASAR；
5. 核验 `electron-log`、`electron-updater` 等生产依赖；
6. EXE 与 ASAR 成对更新；
7. 在测试目录启动并完成冒烟测试。

---

## 7. 主题完成定义

一个主题只有同时满足以下条件才算完成：

- 所有正式资产和来源记录齐全；
- 四个主页面、首次配置和所有弹窗无明显漏皮肤；
- 主、次、危险、图标、导航和筛选按钮状态齐全；
- 反馈核心完整响应全部事件；
- 成功、警告、错误语义清晰且不只依靠颜色；
- 自定义壁纸下文字仍可读；
- reduced-motion 可用；
- 无文字烘焙、无水印、无明显生成瑕疵；
- Vite 构建通过；
- 完整 Electron 包可启动；
- 测试目录验收通过。

---

## 8. 推荐实施顺序

为降低返工，按以下顺序开发：

1. 先选择一个新主题作为模板主题；
2. 完成其概念样张；
3. 完成背景、核心和材质母版；
4. 打通按钮九宫格、卡片、导航和弹窗；
5. 打通反馈核心全事件；
6. 完成 16 组页面验收；
7. 抽取公共主题接口；
8. 再依次生产其余主题。

不建议七套主题同时生图。先用一套完整主题验证资产规格和 CSS 接口，再批量扩展，能够避免七倍返工。
